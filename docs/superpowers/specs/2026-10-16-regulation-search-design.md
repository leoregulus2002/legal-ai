# 法律法规检索第一版设计

日期：2026-10-16。状态：功能方向已确认，详细设计待用户审阅；尚未进入实现。

## 目标与范围

用户已确认先完成“搜索 → 筛选 → 查看全文 → 核对来源 → 复制引用”的流程。
本设计假设主要使用者为律师、法务及需要准确查找原文的用户。
成功标准是能从内部已审核发布的法规资料定位条文，辨认版本和来源，并复制可追溯的原文引用。

第一版提供名称、正文、文号检索，精确查条，法规条件筛选，结果高亮，全文目录、文内搜索及引用复制。
覆盖范围明确限定为内部知识库已发布的 LEGAL 文档；不宣称覆盖全国全部法规。
数据来自现有录入与审核发布流程，不新增外部采集。
语义检索、历史版本关联与差异对比、收藏、检索历史、咨询联动及更新订阅留待后续。

## 现状与方案选择

现有 `modules/knowledge` 已有法律文件模式、结构节点、正文快照、审核发布、效力与来源标记，以及 BM25/向量混合检索。
知识库搜索目前返回片段候选，其条数和排序不能直接当作完整的法规检索统计。
现有法律元数据包含名称、制定机关、文号、公布日期、施行日期和版本说明，尚缺法规类别、适用地区。
工作台和导航已有“法律法规检索”占位入口，尚未连接路由。

考虑三个方案：

1. 在知识库业务内增加法规专用只读接口，前端建立独立检索模块。复用资料生命周期，改动集中，推荐采用。
2. 直接使用现有混合检索接口。开发较少，但难以保证精确匹配、完整分页和筛选计数，不符合第一版目标。
3. 建立独立法规库及搜索服务。需要同步与重新管理数据，当前规模不采用。

后端继续遵守 Router → Service → Repository；检索规则在 Service，数据库筛选、计数和分页在 Repository。
不新增数据库表、后台任务、AI 调用、搜索基础设施或主要依赖。

## 数据与发布边界

所有列表、筛选选项、覆盖统计和全文接口同时要求：知识库未删除、文档未删除、`mode=LEGAL`、`status=PUBLISHED`、`published_at` 非空。
正文及节点来自该文档当前修订的 ParseRevision，命中定位与引用使用同一修订号。
撤回、删除或重新修订的资料立即退出检索；前端缓存的旧链接再次访问时返回简洁的不可用提示。
不通过阅读接口暴露审核草稿、审阅备注、附件原始字节或历史解析修订。

扩展共享 `LegalMetadata`，新增有默认值的 `category` 与 `region`，沿用现有 JSON 存储，无需新增数据库列。
类别使用明确枚举：未分类、宪法、法律、行政法规、监察法规、地方性法规、部门规章、地方政府规章、司法解释、其他。
地区以人工填写的适用地区为准，允许全国或具体行政区；不依据名称推断适用范围。首版按已录入值精确筛选，不自动推断上下级行政区。
旧数据缺失类别或地区时显示“未分类”或“未标注”，不默认全国。
现有文档审核页补充字段编辑，前后端类型同步；已有快照保持可解析，字段修改继续走修订及重新发布流程。

效力状态与来源核验独立展示。人工审核发布不代表官方核验，版本已确认不代表现行有效。
缺少核验信息或效力未知时如实显示；不根据施行日期自动判断失效或现行有效。
`updated_at` 展示为“资料更新时间”，不能写成“官方法规更新时间”或“最近核验时间”。

## 搜索规则

提供全部、名称、正文、文号四种检索范围；提供包含匹配与精确匹配。
包含匹配以去除首尾空白后的查询整体为连续子串，SQL 参数化并转义通配符。
精确名称和文号要求完整字段相等；精确正文要求完整条文内容相等。
全部范围按名称、文号、正文取并集，精确模式分别使用上述规则，不混入语义召回结果。
空查询允许浏览全部已发布法规并使用筛选条件。

搜索结果以“文档及其当前修订”为单位，一份资料只占一条结果，`total` 是满足条件的文档数。
先在完整资料范围内筛选和统计，再排序分页；不沿用混合召回的候选上限。
默认排序依次考虑名称/文号精确命中、名称包含命中、正文命中，再以公布日期降序及文档 ID 稳定排序。
支持公布日期和施行日期升降序，缺失日期排后，ID 作为稳定次序。
每条结果显示代表性命中片段及可定位的条号；一个文档命中多条时展示命中条文数量，详情中可继续查找。
来自不同知识库的同名文档分别展示所属库，不做未经确认的版本合并。

查条支持法规名称或名称子串加“第 N 条”，N 支持中文、阿拉伯数字及“条之 N”。
Service 复用已有数字解析能力；名称和条号联合约束，条号匹配 ARTICLE 节点的 number、suffix，不搜索任意正文数字。
命中多个名称或版本时全部展示，由用户选择；只有条号时要求补充法规名称。
无对应结构条文时显示未找到，不将普通正文匹配伪装为精确查条。

筛选包括知识库、法规类别、制定机关、适用地区、效力状态、公布及施行日期区间。
筛选值之间取交集，日期区间包含两端，未知日期不满足指定区间；开始日期晚于结束日期时阻止提交并弹出提示。
默认效力筛选为全部，用户可以明确选择现行有效，避免隐式丢弃历史或待核验资料。

## 接口边界

在现有知识库模块增加专用静态前缀，并在 `/{base_id}` 动态路由之前注册：

- `GET /api/v1/knowledge-bases/regulations/options`：返回有可检索资料的知识库、已录入机关和地区，以及实际覆盖的文档/知识库数量。
- `GET /api/v1/knowledge-bases/regulations`：接收查询、范围、匹配方式、筛选、排序及页码；返回结果、完整文档总数、页码及每页条数。
- `GET /api/v1/knowledge-bases/regulations/{document_id}`：返回当前已发布元数据、完整正文、只读结构目录、修订号和来源信息；不接收任意修订参数。

搜索结果至少包含 document_id、knowledge_base_id/name、revision、metadata、legal_status、source_kind、version_confirmed、source_url、updated_at、命中摘要及目标条文 node_id。
结果定位链接携带文档 ID、修订号、节点 ID 和查询；详情发现修订变化后提示资料已更新并清除旧定位，不应用失效偏移。
参数使用 Pydantic/Query 约束与统一错误格式。前端不展示原始异常和数据库信息。

## 页面与交互

建立 `frontend/src/modules/regulations`，包含自己的 API、类型、检索页、阅读页及必要组件和样式。
路由为 `/regulations` 与 `/regulations/:documentId`，均按需懒加载。
工作台和左侧导航共用现有 features 配置，将占位入口指向检索页。
沿用当前工作台视觉、公共图标与 Naive UI，不重设计全站。

检索页顶部显示标题、查询框、范围及匹配方式；左侧为筛选，右侧为结果、排序和分页。
窄屏筛选折叠到可展开区域。使用 URL query 保存已提交的查询与筛选，刷新、分享和返回后保持条件。
输入编辑不立即搜索，回车或点击提交后请求；筛选提交及排序变更重置页码。
使用取消请求或序列号忽略过期响应，失败后清除旧结果的当前有效状态，不把上次结果当成本次命中。
页面区分加载、尚无已发布法规、未命中；请求错误统一用 Message/Notification 提示，不写入正文。
有未知元数据的结果用明确标签表达；页面展示内部资料覆盖数量和来源范围，不填充假法规、假统计或假结果。

阅读页展示法规名称、版本、效力、机关、文号、日期、类别、地区、所属库和来源核验状态。
左侧为章节/条文目录，右侧为完整原文；支持目录跳转、文内搜索、前后命中跳转，以及从结果直接定位条文。
正文按纯文本安全渲染，高亮使用文本拆分或 mark 节点，不用未过滤的 v-html。
Python 偏移按 Unicode 码点计数，浏览器切片需统一码点语义，避免非 BMP 字符导致条文错位。
结构节点可能仅覆盖标题，条文复制与定位范围必须延伸到下一个同级或更高层级节点之前，包含完整款项，末条延伸至相应章节结束或全文结尾。

提供“复制本条”和“复制全文引用”。引用由法规名称、完整条号、原文、版本说明、效力状态、来源地址组成；缺失字段标注未提供。
只有有效 HTTP(S) 来源链接允许打开，使用安全的新窗口属性；来源未核验时标注“来源链接”，不标为“官方原文”。
复制失败通过简洁弹出提示处理。返回检索保留 URL 中的条件。

## 改动范围与兼容性

后端主要涉及 knowledge schemas、repository、service、router；复杂查条或摘要规则可按实际需要拆出专用文件。
前端新增 regulations 模块，并修改路由、工作台 features、知识库元数据类型及审核编辑表单。
文档更新 README 和 architecture 中的可用能力与边界，保留原有未提交工作。
不改变法律咨询的内部库范围、既有混合召回协议、知识库管理入口或旧测试配置。

## 实施与验证约束

项目已停止所有功能测试。本任务不运行自动化测试、手动功能测试、浏览器交互测试、API 联通测试、数据库或迁移功能验证。
不以冒烟检查或验证名义执行功能测试；保留既有测试文件和依赖。
实现阶段仅进行用户开发约定要求的 Ruff、vue-tsc、ESLint、Prettier 静态检查/格式化及代码差异审阅，报告实际执行范围。
本设计阶段仅只读检查代码并编写文档，未执行任何测试或运行数据库迁移。
第一版交付说明必须区分已实现内容与未执行的功能测试，不宣称运行正确或测试通过。

## 风险与后续边界

首版数据库包含查询以完整准确为先；规模增长后的索引优化单独基于实际数据评估，不提前引入服务。
缺少类别与地区的旧资料需要在审核页人工补充，不能通过搜索推测补全。
资料更新时间和来源核验标记不能保证法规实时更新，界面不得声称自动保持最新。
按历史日期选择版本、法规适用性判断、版本差异和自动更新均不属于第一版。
