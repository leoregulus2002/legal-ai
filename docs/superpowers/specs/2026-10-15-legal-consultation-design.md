# AI 法律咨询模块设计

日期：2026-10-15。状态：聊天中的设计已确认，本书面方案待用户审阅。

## 1. 已确认的目标与范围

优先完成 AI 法律咨询模块，提供真实模型调用、流式回答、多模态输入和可持续的会话记忆。模型与提示词通过独立菜单维护，不硬编码在咨询页面。

用户已确认：

- 输入支持文字、图片、PDF，首期不包含音频和视频。
- 本次只做知识库接入，不建设知识库录入、文档索引或向量检索系统。
- 知识库开启且未命中时，固定回复“知识库找不到对应信息”。
- 模型配置维护全部可用模型；法律咨询模型配置维护咨询模块允许选择的对话模型。
- 记忆由最近 N 轮完整对话、较早对话摘要和关键词组成。
- 配置统一存入 PostgreSQL；会话运行记忆（最近 N 轮、摘要、关键词和压缩进度）存入 Redis。
- 功能测试保持停止，不执行自动化、手动、浏览器、API 联通或迁移功能验证。

本次请求授权实施上述 AI 能力，超出此前 Phase 1 的基础工程边界。仍沿用模块化单体，不引入认证、Agent、LangGraph、Embedding、采集、支付或其他业务模块。

## 2. 技术方案与选择

采用直接的异步模型协议适配：业务 Service 编排咨询、记忆和知识库，AI 公共层负责协议转换与调用。复用 PostgreSQL、SQLAlchemy、FastAPI 和 Vue/Naive UI，不新增编排框架。

其他可选方案是使用 AI 编排框架，或依赖供应商托管会话；前者增加本次依赖与抽象，后者使跨供应商模型切换和记忆迁移依赖外部会话机制。本次采用应用自己保存会话的方案。

首期实现 OpenAI 兼容 Chat Completions 和 OpenAI Responses 两种协议。兼容供应商通过接口地址、模型标识和数据库中的加密凭据配置；未经实现的协议不允许保存为可用配置。图片和 PDF 能力按协议及模型分别声明，不能把所有“兼容”接口视为具备相同文件能力。

全部模型指本系统已配置的模型目录，不自动抓取供应商模型列表，不预置虚构的可用模型。目录允许区分对话模型和其他模型类型；只有已启用、具备流式文本输出的对话模型可加入法律咨询列表。

## 3. 模块边界

后端：

- `app/modules/system_config`：模型目录、系统提示词、法律咨询模型及默认策略的 Router、Service、Repository、Models、Schemas。
- `app/modules/consultation`：会话、消息、附件、生成请求、Redis 记忆存储及咨询流式流程；持久化 Repository 与 Redis 记忆存储各自封装 I/O。
- `app/ai/providers`：两个协议的异步适配、请求参数、附件转换、流式事件与超时处理。
- `app/ai/retrieval`：知识库检索契约、空库适配和外部 HTTP 适配。
- `app/ai/prompts`：咨询上下文组装及摘要/关键词提取所需的实际提示模板。
- `app/api.py`：统一注册 `/api/v1` 路由。

前端：

- `src/modules/consultation`：咨询页面、会话列表、消息与附件组件、API 和 Pinia 状态。
- `src/modules/system-config`：三个独立配置页面及配置 API。
- `src/api`：统一 Axios 客户端及流式响应处理；复用错误归一化。
- `src/layouts/AppLayout.vue`：增加业务路由和“系统配置”菜单组。

遵守 Router → Service → Repository。Router 不读写数据库，Repository 不执行模型调用或业务判断。AI 公共层不依赖业务 Router。不创建没有用途的空目录、通用 CRUD 框架或抽象基类。

## 4. 菜单与页面

```text
工作空间
  工作台
  AI 法律咨询
系统配置
  系统提示词
  模型配置
  法律咨询模型
```

保留现有法律工作台的海军蓝、象牙白和古铜色样式。咨询页面包含历史会话列表、当前消息区域和输入区；顶部提供模型选择、系统提示词选择及知识库开关。输入区支持文字、图片预览、PDF 文件项、发送和停止生成。

提示词选择只显示已启用的模板，默认使用法律咨询配置指定的模板；不把提示词正文混入用户消息。模型切换作用于下一次发送，流式生成过程中锁定模型、提示词、知识库开关和附件编辑，避免一条回答使用混合配置。

模型配置页面维护名称、类型、协议、Base URL、模型标识、API Key、启停状态、上下文预算、输出上限及图片/PDF 能力，全部保存到 PostgreSQL。API Key 仅允许输入、替换或明确清除，读取时返回是否已配置。可选参数只在该模型支持时发送。页面不提供模型联通测试按钮。

系统提示词页面维护名称、正文和启停状态，并保留版本；编辑产生新版本，历史回答继续引用原版本。

法律咨询模型页面从模型目录选择可用对话模型，维护默认模型、默认系统提示词、最近 N 轮、摘要长度、关键词数量和记忆有效期；同时提供本模块的知识库接入、上传限制及调用超时设置。这些业务配置全部保存到 PostgreSQL。N 默认 6，允许 1–30；摘要默认最多 2000 字，关键词默认最多 12 个；记忆默认最后使用后 7 天过期，允许配置 1–90 天。配置变更影响后续发送，历史消息保存当时使用的配置快照，不包含凭据。

未配置可用咨询模型时显示配置入口并禁止发送。未命中知识库是正常回答内容；请求异常及业务错误仅用 Naive UI Message 弹出，不渲染原始异常或错误卡片，也不写成助手消息。

## 5. 模型配置与凭据

模型配置、系统提示词及版本、法律咨询可用模型与默认策略、知识库接入参数、记忆策略、上传限制和调用参数统一存入 PostgreSQL。业务配置从数据库读取，不要求修改环境变量才能在管理页面生效。

模型及外部知识库的 API Key 也保存到 PostgreSQL，使用 Fernet 认证加密后存储密文。加密主密钥由后端 Pydantic Settings 从环境变量加载，不与密文同库存放，也不返回给前端。该基础设施启动密钥与数据库/Redis 连接地址、附件物理目录仍属于部署配置，不在业务菜单中维护。

前端表单支持设置或替换 API Key；编辑时不回填原值，未提交密钥字段表示保留，清除使用明确操作。服务端只返回凭据是否已配置；明文仅在提交和调用所需的短暂内存中存在，不进入浏览器持久化存储、业务日志或配置快照。主密钥缺失或无法解密时报告配置异常，不覆盖或清空已有密文。

已停用或删除的模型无法被用于新请求。被历史消息引用的配置采用停用或归档，避免破坏历史追溯。

Base URL 必须是完整的 HTTP(S) 地址，不含用户名、密码、查询参数或片段；本地模型允许明确配置的本地 HTTP 地址。供应商请求不自动跟随重定向，避免将凭据转发到其他地址。

切换模型时保留同一会话的文本历史、摘要和关键词。若当前附件或最近 N 轮中需要发送的附件不被新模型支持，发送前提示兼容性问题，不静默丢弃附件；用户可以选择兼容模型或新建会话。

## 6. 知识库接入

定义统一检索输入：当前问题、对话关键词、历史摘要和最大结果数。定义检索结果：资料 ID、标题、正文片段、来源和相关度。所有外部返回按 Pydantic 约束检查类型、数量和长度。

提供两种状态：

1. 没有配置知识库接口时，使用显式的空库适配，返回零条命中。
2. 配置外部接口时，通过异步 HTTP 适配查询；接口地址、加密凭据、超时、结果上限和相关度阈值来自 PostgreSQL 中的法律咨询配置。

首期 HTTP 接入契约：向配置地址发送 POST，正文为 `query`、`keywords`、`history_summary`、`limit`；响应为 `matches` 数组，每项包含 `id`、`title`、`content`、`source`、`score`。`score` 范围为 0–1，阈值默认 0.7、结果上限默认 5；该阈值是可配置的筛选规则，不代表法律准确率。

知识库关闭时不调用检索。开启时只使用当前检索命中的资料作为回答依据，要求引用结果编号，页面展示实际来源。历史模型回答、摘要和用户附件可提供问题背景，不作为法律依据。对图片/PDF 的知识库查询使用本次输入文字和会话背景；首次知识库咨询必须提供文字问题，纯附件发送提示补充检索问题。

零条合格结果时直接通过咨询流返回“知识库找不到对应信息”，不调用回答模型补充法律结论。超时、接口不可达、响应结构错误属于检索失败，终止本次请求并弹出简洁提示，不能伪装成知识库未命中。

不构建资料录入、文件索引、Embedding、向量表或知识库管理菜单。空库适配不返回任何示例法规、虚构片段或模拟引用。

## 7. 多模态附件

图片首期允许 JPEG、PNG、WebP，PDF 允许 `.pdf`。后端检查实际文件类型、大小和数量，不仅依赖文件名或浏览器 MIME。默认每条消息最多 5 个附件、单文件最多 10 MiB、总大小最多 20 MiB，限制保存在 PostgreSQL 的法律咨询配置中并返回给前端。

附件使用随机存储标识，保存在 Git 忽略的本地数据目录，数据库保存文件元数据和关联。采用异步 I/O；不接受任意本地路径或用户提供的远程 URL 代替上传。访问通过受控附件接口，不把存储目录直接作为静态文件根目录暴露。

图片/PDF 通过协议适配转换为模型原生输入，不假造 OCR 或文档解析结果。上传的 PDF 是咨询附件，不自动进入知识库。模型未声明支持的输入类型在调用前拒绝。

已绑定消息的附件随会话保存；删除会话清理其附件。未发送附件保留 24 小时，由服务端按生命周期清理；失败的生成不生成持久化的用户/助手消息。

## 8. 会话记忆

一轮指一条用户消息和对应的完整助手回答。会话及完整历史消息保存在 PostgreSQL，供历史展示和 Redis 记忆恢复使用；模型实际使用的最近 N 轮上下文、摘要、关键词及摘要覆盖进度统一保存在 Redis，不创建数据库记忆表。输入模型的上下文包含：

1. 本次选定的系统提示词及知识库约束。
2. 较早已完成对话的摘要和关键词，明确标记为会话背景。
3. 最近 N 轮完整消息，按时间顺序排列。
4. 当前用户输入、附件及本次知识库命中资料。

超过 N 轮的历史逐步合并到摘要。Redis 单个记忆快照记录最近 N 轮消息及附件标识、摘要覆盖到的轮次、摘要版本、关键词、策略版本和对应的数据库历史版本，防止重复压缩或遗漏；关键词保留当事人、时间、金额、争议事项等已在对话出现的信息，不自动补充事实。附件二进制文件不写入 Redis。

摘要由真实模型调用生成结构化结果，使用所选对话模型和独立的摘要指令；仅压缩已完成的轮次。需要处理历史图片/PDF 时，使用支持该输入的模型；不能从文件名推断其内容。摘要失败或结果不合规时保持旧记忆和完整历史，提示后终止本次生成，不静默丢弃历史。

上下文需要压缩时先在请求内存中准备新摘要，答案完成后才发布新的 Redis 记忆快照；本轮失败时不推进摘要边界。停止或失败的部分回答不计入 N 轮，不加入摘要和关键词。上下文超过模型预算时提示调整 N、附件或模型，不在未告知情况下截断用户输入。预算检查采用协议支持的计数方式或保守估算，明确估算不是供应商精确 token 计数。

Redis Key 使用 `legal-ai:consultation:{conversation_id}:memory`，通过一次原子写入保存整份快照并设置有效期，成功读取或更新时续期。记忆、附件、关键词只在当前会话内使用，不跨会话共享。删除会话时删除对应 Redis Key；即使清理暂时失败，后续读取也先检查数据库会话是否存在，且过期机制最终清除残留。

Redis Key 过期、丢失，或记忆的历史版本/策略版本与数据库不一致时，在该会话的生成占用内，从 PostgreSQL 已完成历史重建最近 N 轮、摘要和关键词，再继续咨询。较长历史分批压缩，所有新增摘要来自真实模型调用；不能把空摘要冒充恢复成功。重建失败时不发送缺失上下文的新问题，也不改写完整历史。

Redis 连接不可用时暂停咨询生成并提示记忆服务暂不可用，不静默退化为无记忆对话。Redis 不是配置的权威来源，数据库仅保留完整历史和版本信息，不备份一份可变摘要或关键词。

## 9. 流式输出与事务

采用 POST + SSE 格式响应，浏览器通过统一 Axios 客户端的流式传输能力读取内容。流式 API 使用独立的长超时、取消信号及心跳机制，普通配置请求保留现有超时。

事件类型：`start`（生成 ID 与配置摘要）、`sources`（真实检索来源）、`delta`（新增回答文本）、`done`（保存成功后的消息 ID）、`error`（脱敏错误码与用户提示）。SSE 不暴露上游响应正文、堆栈、凭据或内部提示模板。

按顺序校验会话、可用模型、提示词、附件和并发状态，然后执行检索、上下文组装和上游流式调用。模型配置和提示词在请求开始时形成快照，配置编辑不改变正在进行的回答。

每个会话同时允许一个生成。客户端请求带幂等 ID，数据库唯一约束防止重复消息；生成占用状态有期限并按活动续期，进程异常后可恢复。生成记录仅管理状态，不把失败尝试混入成功消息历史。记忆重建与配置变更后的记忆重算也在同一生成占用内串行执行。

流式发送不能继续使用 `scope="function"` 的请求 Session。Service 使用应用 session factory，在准备、占用续期和结束阶段分别管理短事务；上游调用期间不持有数据库事务。回答成功完成后，用户消息、助手消息、来源、脱敏配置快照和递增的会话历史版本在同一 PostgreSQL 事务中保存。

PostgreSQL 和 Redis 不共享事务：先提交完整消息，再根据已提交的历史版本原子发布 Redis 记忆；写入时拒绝用旧版本覆盖新快照。数据库提交前的失败不改变已有记忆。数据库已提交而 Redis 更新失败时，保留已成功保存的回答，通过 `done` 附带 `memory_status: rebuild_required` 告知客户端，前端显示一次简洁通知；不能声称本轮回滚或重新调用模型。下次生成必须先恢复 Redis 连接并按数据库历史版本重建记忆。

停止生成、断开连接、上游错误或数据库提交前的保存失败时关闭上游流，回滚本轮消息，保留旧 Redis 记忆并释放生成占用。客户端清除未保存的临时回答并保留待发送输入，通过弹窗反馈异常；已成功提交但客户端未收到 `done` 时，重新读取历史并通过幂等 ID 识别已保存的结果，不重复调用模型。

## 10. 数据与接口

PostgreSQL 实体为模型配置及加密凭据、提示词与版本、咨询模型关联和默认策略、知识库接入参数、会话及历史版本、完整消息、附件和生成状态。Redis 保存最近 N 轮、摘要、关键词、压缩进度及版本组成的会话记忆，不为这些记忆内容建立 PostgreSQL 表。使用 SQLAlchemy 2 Mapped、AsyncSession 和 Alembic 手写迁移；不使用 `create_all`。

路由分组：

- `/api/v1/system-config/models`：模型目录维护和能力信息。
- `/api/v1/system-config/prompts`：提示词维护和版本。
- `/api/v1/system-config/consultation`：可用咨询模型、默认策略、记忆策略、知识库接入和运行参数。
- `/api/v1/consultation/options`：咨询可选模型、提示词和附件限制。
- `/api/v1/consultation/conversations`：会话列表、新建、读取和删除。
- `/api/v1/consultation/conversations/{id}/messages`：分页读取完整历史。
- `/api/v1/consultation/conversations/{id}/stream`：提交输入并流式生成。
- `/api/v1/consultation/attachments`：上传和读取附件，删除未绑定附件。

配置接口只返回脱敏内容。输入使用 Pydantic 2 验证，前端严格 TypeScript，不通过 `any` 绕过约束。分页、长度、数量及并发限制由 Service 统一执行。

新增 `httpx`、凭据加密所需的 `cryptography` 等生产依赖只在实际使用时添加，更新 `uv.lock`；若新增前端依赖，同步更新 `pnpm-lock.yaml`。真实密钥、附件、环境文件和构建产物不得进入 Git。`.env.example` 仅记录基础设施参数及加密主密钥的配置说明，不保存业务模型或提示词配置。

允许的代码检查为 Ruff、vue-tsc、ESLint、Prettier 和静态代码审阅。所有功能测试继续停止；不启动浏览器交互、不探测模型或知识库接口、不连接数据库执行迁移验证。保留现有测试文件与命令，最终如实报告未执行功能测试。

设计落实后的审阅标准是：七项需求均有明确代码入口；模型与提示词可独立配置；空库分支固定回复；真实调用与流式保存有明确边界；附件能力校验和 N 轮/摘要/关键词策略完整。静态检查通过不能替代运行效果或模型质量确认。
