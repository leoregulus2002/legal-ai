# AI 法律咨询使用与接入

## 启动前准备

依赖已在 `backend/pyproject.toml`、`backend/uv.lock` 中声明。仍使用 Python 3.13、已有的 Node.js 26 与 pnpm。

1. 在 `backend` 目录执行 `uv sync --locked` 安装后端依赖。
2. 在本地 `backend/.env` 设置 `CONFIG_ENCRYPTION_KEY`。可用以下命令生成 Fernet 主密钥，再将输出保存到被 Git 忽略的 `.env`：

   ```bash
   uv run python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
   ```

   主密钥用于加解密数据库里的模型 API Key，必须与数据库一起妥善备份。更换主密钥前需要迁移已有密文；直接丢失或替换会使原凭据无法读取。后端不向前端返回密钥值。

3. `0002_consultation.py` 创建配置、提示词版本及会话历史表；`0003`、`0004` 增加内部知识库和向量配置；`0005_hybrid_retrieval.py` 增加正式片段的 BM25 词频索引。本次开发按用户要求没有执行迁移或迁移验证；实际使用新增功能前，需要用户自行在开发数据库应用迁移：

   ```bash
   uv run alembic upgrade head
   ```

4. 按 README 启动后端、前端及 PostgreSQL/Redis。反向代理需关闭咨询流的响应缓冲，并使读取超时大于配置的生成总超时；后端已返回 `X-Accel-Buffering: no`。

## 配置顺序

1. 打开“系统配置 → 模型配置”，添加真实模型的显示名称、接口协议、Base URL、模型标识和 API Key。
2. Base URL 包含版本路径，例如供应商规定的 `/v1`，不要填写完整 `/chat/completions` 或 `/responses` 路径。
3. 按模型文档设置上下文预算、输出上限、图片/PDF 能力。Chat Completions 的输出上限参数可选择 `max_tokens` 或 `max_completion_tokens`。Temperature 留空时不发送该参数。
4. “支持 JSON 模式”仅在供应商明确支持时开启；关闭时仍通过提示要求摘要返回 JSON，并严格校验返回结构。
5. 按需在“系统提示词”添加提示词，编辑会产生新版本；也可确认删除提示词及其全部版本。删除默认提示词时会自动清空默认项，历史对话中的提示词快照保留。
6. 在“法律咨询模型”选择可用对话模型、默认模型，按需选择默认系统提示词（可清空），在“知识库接入 → 添加内部知识库”多选要用于咨询的知识库，保存记忆策略和附件限制。
7. 打开“AI 法律咨询”菜单进入对话页。页面自动使用已配置的默认系统提示词，未配置时也可正常咨询，不显示提示词选择器；在输入框底部、发送图标左侧切换模型和知识库开关。切换模型作用于下一条消息，同一会话的记忆延续。

所有业务配置存 PostgreSQL，模型 API Key 加密入库；环境变量只维护数据库/Redis 连接、加密主密钥、附件物理目录等部署参数。内部知识库无需填写外部接口地址或专用 API Key。没有可用模型时，页面提供配置入口，不返回模拟答案。系统提示词为可选配置；生成请求的 `prompt_id` 可省略或为 `null`，此时不加载自定义提示词，仍保留会话记忆、附件和知识库资料的基础处理规则。无提示词的历史快照将 `prompt` 保存为 `null`。

## 多模态与流式行为

- 支持文字、JPEG/PNG/WebP 图片和 PDF。只有声明支持相应输入的模型可使用该附件。
- 支持在输入框粘贴附件自动上传；有待发送附件时，无需填写文字即可发送。
- 发送后立即清空输入区的文字和附件，在聊天消息中展示附件；图片显示缩略图，点击打开大图预览，其他附件可点击下载。发送失败且未保存时恢复草稿。
- 模型端必须真实支持所选协议和附件内容格式；仅勾选能力不能使供应商获得该能力。
- 附件默认每条消息最多 5 个，单个 10 MiB，总计 20 MiB，可在法律咨询配置中调整。
- 附件保存在 `ATTACHMENT_DIRECTORY`（默认 `backend/data/attachments`），元数据保存在数据库；PDF 不自动进入知识库。
- 页面实时显示回答，支持停止。点击停止仅终止生成，聊天区保留本次提问、附件和已生成内容并标记“已停止”，不会将本次消息退回输入区。停止的消息暂存在当前应用会话中，不作为完整回答保存到服务端历史或会话记忆；刷新页面后不保留。发送失败且未保存时恢复待发送输入以便重试。
- 模型公开返回的思考内容单独流式显示在可折叠的“思考过程”中，正文开始输出后自动收起。支持 Chat Completions 的 `delta.reasoning_content`、Responses 的 `response.reasoning_text.delta` 和 `response.reasoning_summary_text.delta`。没有思考内容时不展示此区域，不从正文猜测或生成思考过程。
- 完整消息的思考内容保存在独立的 `consultation_turns.reasoning` 字段，历史消息可展开查看；停止生成时，已经收到的思考内容随本次消息在当前应用会话中保留。思考内容不加入后续提问的正文、会话记忆或摘要输入。
- 刷新页面、停止或断开流式连接时，后端在屏蔽外层取消的清理区内结束生成任务，并用独立短事务释放会话占用；两步分别最多等待 5 秒。释放失败会记录脱敏告警，由最后一次续期后 45 秒的租约兜底过期。刷新后立即重发可能与清理短暂重叠；真正仍在生成的会话继续拒绝并发请求，不强制覆盖有效占用。
- 对话区域占满主内容区，输入框使用圆角布局；左下角加号添加附件，右下角箭头发送，生成中变为停止图标。Enter 发送，Shift + Enter 换行。
- 服务端只有保存完整消息后才发送 `done`。前端直接使用该事件中的完整消息更新历史、附件绑定和会话列表；仅在未收到 `done` 时通过发送标识核对完整历史，处理保存成功但连接中断的情况。
- 未发送附件 24 小时后可清理，服务端每小时及上传前执行清理；删除会话同时清理其附件。

### 思考内容的启用与迁移

更新后需在 `backend` 目录执行 `uv run alembic upgrade head`，应用 `0006` 迁移后再启动后端。此迁移为历史消息填充空思考内容。本次仅提供迁移源码，未执行数据库迁移或功能测试。

本次接入负责显示供应商已经返回的内容，不自动开启模型的思考模式，也不向所有兼容接口统一添加思考参数。模型是否启用思考、是否提供可见内容由供应商和模型配置决定。OpenAI 的推理摘要需要单独请求 `reasoning.summary`，当前应用尚未提供该请求参数的配置入口，因此不会默认请求摘要。只返回内部推理 Token 数或加密内容的响应不显示为思考文本。

协议参考：[百炼 Responses 事件](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)、[DeepSeek 流式响应字段](https://api-docs.deepseek.com/api/create-chat-completion/)、[OpenAI 推理摘要事件](https://developers.openai.com/api/reference/resources/responses/streaming-events)、[OpenAI 推理摘要启用方式](https://developers.openai.com/api/docs/guides/reasoning)。

### 模型调用返回 403

咨询接口先建立 SSE 连接，因此访问日志的 HTTP 200 只表示流已建立，不能据此判断模型调用成功。流内的 `error` 事件表示生成失败，只有 `done` 表示完整消息已保存。

供应商 HTTP 请求失败时，后端日志会记录 `status`、`protocol`、`provider_code` 和 `provider_request_id`；无法读取的标识记为 `unknown`。日志不记录原始响应体、API Key 或咨询内容，前端仍通过统一弹出提示呈现简短错误。

阿里云百炼 403 需按实际 `provider_code` 排查：模型调用授权（`Model.AccessDenied`）、工作空间访问权限（`Workspace.AccessDenied`），或免费额度限制（`AllocationQuota.FreeTierOnly`）等。核对 Base URL 对应的工作空间、地域与 API Key，以及目标模型的可用权限；不要仅凭 403 判断协议不兼容或直接切换协议。详见[百炼错误码文档](https://help.aliyun.com/zh/model-studio/error-code)。本项目模型配置及 API Key 存于 PostgreSQL，应在“系统配置 → 模型配置”中修改。

### 长时间等待后模型未完成回答

流内的失败与 HTTP 错误分开处理。Responses 的 `response.incomplete` 会读取 `response.incomplete_details.reason`，`response.failed` 会读取嵌套的 `response.error.code`；Chat Completions 读取 `finish_reason`。输出达到上限、内容限制、上下文超限、限流及超时会返回各自的简短提示；未知原因仍提示服务未完成回答，不直接展示供应商原文。

`max_output_tokens` 或 `length` 表示生成触及输出预算，需按所用模型的文档检查最大输出 Token。部分推理模型的输出预算包含内部推理 Token，可能等待较久但尚未输出正文就耗尽预算，不能仅按可见答案长度设置上限。参见 [OpenAI 推理模型文档](https://developers.openai.com/api/docs/guides/reasoning)。不要把输出超限当作请求超时，也不要在未确认原因时直接延长超时。

后端会记录知识库检索与记忆准备各自的耗时，以发送标识 `request_id` 关联；咨询失败记录应用错误 `code`。模型流失败额外记录事件、结束原因、供应商错误码、供应商请求或响应标识、调用耗时、配置的输出上限及供应商提供的输出/推理 Token 用量。供应商未提供的字段记为 `unknown` 或 `None`，不推测实际原因，也不记录题目、检索正文、模型原文或密钥。此前未记录的流内失败细节无法从旧日志恢复。

百炼 Responses 的 `qwen3.8-flash` 默认思考强度为 `xhigh`，其 `max_output_tokens` 包含思考与正文；如果输出预算仅为 4096，需要留意思考耗尽预算的情况。应以 `response.incomplete` 的结束原因和 Token 用量确认，不能仅凭等待时长下结论。百炼支持用 `reasoning.effort` 调低思考强度，当前应用尚未提供该配置项，不能把供应商默认强度当作低思考模式。参数语义与其他千问系列存在差异，详见[百炼 Responses 文档](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses)。

“咨询生成任务清理异常 type=AppError”也不能独立用于判断根因：旧逻辑会在主流程已处理生成失败后，于清理阶段再次等待同一任务并重复记录原异常。现在已处理的任务异常不再作为清理异常重复告警，未处理的清理异常仍记录错误类型及应用错误码。

## 记忆存储

完整历史保存在 PostgreSQL；运行记忆保存在 Redis，Key 为 `legal-ai:consultation:{conversation_id}:memory`，内容是尚未压缩的完整对话、摘要、关键词、压缩进度及版本。配置项“上下文压缩间隔（N 轮）”沿用存储字段 `recent_turns`，默认 N=6、摘要最多 2000 字、关键词最多 12 个、有效期 7 天；使用后续期。

正常回答输出结束后，直接保存完整消息并缓存本轮原文，不等待额外的摘要模型调用。每累计新增 N 轮已完成对话，在下一次回答前调用模型，将这 N 轮整批合并进已有摘要、同步更新关键词，再开始累积下一批。未满 N 轮时直接使用原文，不为更新关键词单独调用模型。正常缓存最多保留 N 轮尚未压缩的原文，压缩后保留摘要和后续新对话，不再逐轮淘汰旧对话。

例如 N=6 时，第 1–6 轮提问前不压缩，第 7 轮回答前合并第 1–6 轮；下一次在第 13 轮回答前合并第 7–12 轮，再下一次在第 19 轮回答前合并第 13–18 轮。压缩节点固定为完成 N、2N、3N……轮之后，不在每轮提问前重复压缩。

缓存失效后的历史重建同样按 N 轮分批压缩，最后未满 N 轮的原文保留。压缩策略版本已更新，旧滑动窗口缓存会在下一次正常生成时从完整历史重建，避免沿用旧的压缩边界；无需修改数据库结构或删除历史记录。

压缩期间，服务端发送 `status` 事件（`phase: compressing_context`），对话中的状态显示“压缩上下文”；压缩完成发送 `phase: generating`，恢复“生成中”。这属于当前请求的处理状态，不写入回答或历史消息；失败与停止后的提示仍通过统一弹窗处理。压缩失败时终止新请求并提示，已完成回答仍保留，不发送缺失上下文的新问题。上下文用量在压缩前按缓存原文估算，压缩后实际输入会有所变化。

Redis 记忆过期、丢失或配置改变时，正常模型回答会从已完成历史重建上下文。摘要和关键词由实际模型调用产生，不补造对话事实。恢复或摘要失败会提示异常，不静默发送缺失上下文的请求。

数据库和 Redis 不共享事务：先提交完整回答，再原子发布对应版本的记忆。Redis 更新失败时回答仍保留，页面提示记忆需要恢复；后续生成先重建记忆。Redis 无法连接时暂停生成。

内部知识库未命中时不调用回答或摘要模型；如果存在可用向量索引，检索阶段仍会调用 Embedding 模型处理问题。未命中轮次的记忆只使用真实对话原文摘录和从问题原文提取的词项；摘录达到摘要容量、待压缩轮次含附件或已有缓存失效时，保留旧记忆和完整数据库历史，暂缓发布新记忆，待后续需要完整背景时再恢复。附件内容不会由文字摘录替代。

## 内部知识库混合召回

在“法律咨询模型 → 知识库接入 → 添加内部知识库”中选择一个或多个已有知识库。法律咨询仅搜索所选库中已审核发布的资料；BM25 语料统计、两路候选及向量模型发现都限定在该范围内。知识库中的“正式内容搜索”使用相同召回流程，仍限定在当前知识库。

1. 使用 jieba 对正文建立词项频次索引，查询和正文统一字符宽度与大小写。查询过滤泛词，保留数字、法律术语和否定词，最多使用 32 个不同词项。BM25 在数据库中计算词项稀有程度、频次和片段长度，参数为 `k1=1.2`、`b=0.75`。
2. 存在已启用且配置指纹匹配的 Embedding 模型时，同时使用问题向量进行余弦检索。每次只查询同一模型空间和维度的片段；可在搜索页指定模型，默认按已发布资料选择可用模型。
3. 每路最多取得 50 个候选，按正式片段 ID 去重，并以 `sum(1 / (60 + rank))` 融合两路排名。相同片段命中两路时累加分数，不按文本相似度删除例外或相邻条款。不使用 MMR 或重排序模型。
4. 仅检索未删除知识库中未删除、已发布文档的当前版本。没有可用向量索引时使用 BM25 单路并标注“关键词检索”；真实向量服务失败时提示异常，不能伪装为无命中。

最低向量相似度默认 `0.3`，最低关键词覆盖率默认 `0`。覆盖率门槛为 0 时，关键词路仍要求至少命中一个有效查询词。旧配置缺失这两个字段时自动使用默认值。融合分数与两路候选分数分别记录；最多引用资料数默认仍为 5 条。

搜索响应中的 `fusion_score` 用于最终排序，`bm25_score`、`cosine_score`、`keyword_coverage`、`lexical_rank`、`vector_rank` 保留各路的分数和排名。兼容字段 `score` 使用余弦分数或词项覆盖率，通过 `score_type` 区分，不能作为法律适用概率。`retrieval_method` 表示实际执行的是 `hybrid` 或 `keyword`。搜索分页的 `total` 表示本次最多 100 个候选的数量，不代表全库所有相关片段的精确数量。

迁移后启动服务，后台维护任务按每批 100 个正式片段补建历史词频索引，支持中途恢复。新资料发布时在同一事务中生成词频索引；撤回、删除与重新发布同步作用于正式索引。索引尚未准备完成时，通过统一弹出提示告知用户稍后再试，不返回部分索引的查询结果。

本次未执行迁移、索引补建、Embedding 调用或召回准确率评估。混合召回代码的静态检查不能证明实际准确率已经提升。

## 知识库配置与历史兼容

未选择知识库时，可以保存其他咨询配置，但不能启用知识库对话，页面通过弹出提示引导先添加内部知识库。所选库已被删除时需重新配置，不扩大检索范围，也不将配置问题伪装成无命中。所选库均可用但没有合格资料时，固定回答“知识库找不到对应信息”。

`knowledge_base_ids` 保存在现有咨询策略 JSON 中，本次选择器调整无需新增数据库迁移。旧策略缺少该字段时默认为空，需要重新选择并保存；不会自动授权搜索所有内部库。旧的外部 URL、专用 API Key 与外部相关度参数不再参与咨询检索，已有数据库凭据列和历史来源快照保留。

知识库检索使用文字问题；同时上传的图片/PDF 可以作为背景附件。仅发送附件时，本次跳过知识库检索，直接由支持相应附件的模型处理，不改变页面上的知识库开关，之后发送文字仍按开关状态检索。命中时回答只以本次资料作为法律依据，页面展示真实来源。关闭知识库时不进行知识检索。
