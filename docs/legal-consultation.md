# AI 法律咨询使用与接入

## 启动前准备

依赖已在 `backend/pyproject.toml`、`backend/uv.lock` 中声明。仍使用 Python 3.13、已有的 Node.js 26 与 pnpm。

1. 在 `backend` 目录执行 `uv sync --locked` 安装后端依赖。
2. 在本地 `backend/.env` 设置 `CONFIG_ENCRYPTION_KEY`。可用以下命令生成 Fernet 主密钥，再将输出保存到被 Git 忽略的 `.env`：

   ```bash
   uv run python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
   ```

   主密钥用于加解密数据库里的模型/知识库 API Key，必须与数据库一起妥善备份。更换主密钥前需要迁移已有密文；直接丢失或替换会使原凭据无法读取。后端不向前端返回密钥值。

3. `0002_consultation.py` 创建配置、提示词版本及会话历史表。本次开发按用户要求没有执行迁移或迁移验证；实际使用新增功能前，需要用户自行在开发数据库应用迁移：

   ```bash
   uv run alembic upgrade head
   ```

4. 按 README 启动后端、前端及 PostgreSQL/Redis。反向代理需关闭咨询流的响应缓冲，并使读取超时大于配置的生成总超时；后端已返回 `X-Accel-Buffering: no`。

## 配置顺序

1. 打开“系统配置 → 模型配置”，添加真实模型的显示名称、接口协议、Base URL、模型标识和 API Key。
2. Base URL 包含版本路径，例如供应商规定的 `/v1`，不要填写完整 `/chat/completions` 或 `/responses` 路径。
3. 按模型文档设置上下文预算、输出上限、图片/PDF 能力。Chat Completions 的输出上限参数可选择 `max_tokens` 或 `max_completion_tokens`。Temperature 留空时不发送该参数。
4. “支持 JSON 模式”仅在供应商明确支持时开启；关闭时仍通过提示要求摘要返回 JSON，并严格校验返回结构。
5. 按需在“系统提示词”添加提示词，编辑会产生新版本；也可确认删除提示词及其全部版本。删除默认提示词时会自动清空默认项，历史对话中的提示词快照保留。
6. 在“法律咨询模型”选择可用对话模型、默认模型，按需选择默认系统提示词（可清空），保存记忆策略和附件限制。
7. 打开“AI 法律咨询”菜单进入对话页。页面自动使用已配置的默认系统提示词，未配置时也可正常咨询，不显示提示词选择器；在输入框底部、发送图标左侧切换模型和知识库开关。切换模型作用于下一条消息，同一会话的记忆延续。

所有业务配置存 PostgreSQL，模型与知识库 API Key 加密入库；环境变量只维护数据库/Redis 连接、加密主密钥、附件物理目录等部署参数。没有可用模型时，页面提供配置入口，不返回模拟答案。系统提示词为可选配置；生成请求的 `prompt_id` 可省略或为 `null`，此时不加载自定义提示词，仍保留会话记忆、附件和知识库资料的基础处理规则。无提示词的历史快照将 `prompt` 保存为 `null`。

## 多模态与流式行为

- 支持文字、JPEG/PNG/WebP 图片和 PDF。只有声明支持相应输入的模型可使用该附件。
- 模型端必须真实支持所选协议和附件内容格式；仅勾选能力不能使供应商获得该能力。
- 附件默认每条消息最多 5 个，单个 10 MiB，总计 20 MiB，可在法律咨询配置中调整。
- 附件保存在 `ATTACHMENT_DIRECTORY`（默认 `backend/data/attachments`），元数据保存在数据库；PDF 不自动进入知识库。
- 页面实时显示回答，支持停止。失败/停止的未保存回答不进入完整历史和会话记忆，待发送输入保留以便重试。
- 对话区域占满主内容区，输入框使用圆角布局；左下角加号添加附件，右下角箭头发送，生成中变为停止图标。Enter 发送，Shift + Enter 换行。
- 服务端只有保存完整消息后才发送 `done`。前端通过发送标识核对完整历史，处理保存成功但连接中断的情况。
- 未发送附件 24 小时后可清理，服务端每小时及上传前执行清理；删除会话同时清理其附件。

## 记忆存储

完整历史保存在 PostgreSQL；运行记忆保存在 Redis，Key 为 `legal-ai:consultation:{conversation_id}:memory`，内容是最近 N 轮、摘要、关键词、压缩进度及版本。默认 N=6、摘要最多 2000 字、关键词最多 12 个、有效期 7 天；使用后续期。

Redis 记忆过期、丢失或配置改变时，正常模型回答会从已完成历史重建上下文。摘要和关键词由实际模型调用产生，不补造对话事实。恢复或摘要失败会提示异常，不静默发送缺失上下文的请求。

数据库和 Redis 不共享事务：先提交完整回答，再原子发布对应版本的记忆。Redis 更新失败时回答仍保留，页面提示记忆需要恢复；后续生成先重建记忆。Redis 无法连接时暂停生成。

没有配置知识库 URL 的明确空库路径不调用模型，包括摘要调用。未命中轮次的记忆只使用真实对话原文摘录和从问题原文提取的词项；摘录达到摘要容量、待压缩轮次含附件或已有缓存失效时，保留旧记忆和完整数据库历史，暂缓发布新记忆，待后续需要完整背景时再恢复。附件内容不会由文字摘录替代。

外部知识库检索需先取得版本有效的完整会话背景；记忆缺失时使用摘要模型恢复后再查询，恢复失败报告记忆异常，不能用缺失事实的检索结果误报未命中。成功检索后未命中不调用回答模型，直接返回固定文字。

## 知识库 HTTP 接入契约

本次仅提供接口接入，不包含录入、索引、Embedding 或向量检索。未填写检索接口时视为空库。

在“法律咨询模型 → 知识库接入”设置检索 URL、可选 API Key、相关度阈值、结果上限和超时。请求使用 POST；如配置了密钥，通过 `Authorization: Bearer ...` 发送。

请求结构：

```json
{
  "query": "本次用户的文字问题",
  "history_summary": "会话摘要与近期问题背景",
  "keywords": [],
  "limit": 5
}
```

响应结构为 `{"matches": [...]}`；每项必须包含以下字段：

| 字段 | 类型与要求 |
| --- | --- |
| `id` | 资料标识，字符串，1–200 字符 |
| `title` | 资料标题，字符串，1–300 字符 |
| `content` | 检索片段，字符串，1–12000 字符 |
| `source` | 来源说明或 HTTP(S) 链接，最多 2000 字符 |
| `score` | 0–1 的相关度，需与本系统阈值处于相同尺度 |

无命中必须返回 `{"matches": []}`。系统过滤低于阈值的资料，默认阈值 0.7、上限 5 条。知识库开启且无合格命中时，固定回答“知识库找不到对应信息”；接口超时、HTTP 异常和结构错误均提示知识库异常，不伪装成空库。

知识库模式必须提供文字问题；图片/PDF 可以作为背景附件。命中时回答只以本次资料作为法律依据，页面展示真实来源。关闭知识库时不调用检索接口。
